# Patient consent (research part 8a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record each patient's signed bilingual consent (four yes/no items, version, language, scanned form), print the form, flag patients with no consent, and carry research consent into the Research page and export as a warning and a coded column.

**Architecture:**
- **Migration 0072** adds `stored_files` (bytes kept out of the audit), `consent_form_versions` (seeded v1, locked once used) and `patient_consents`, with definer writers and invoker readers.
- **Export and Research page:** two new readers. A counts reader feeds the page warning and the export's about sheet. A per-patient reader feeds the export's `research_consent` column, merged in TS by `patient_code`. 0070's readers are not changed.
- **UI:**
  - a Consent tab with upload (browser-side JPEG downscale), void and history;
  - a header badge;
  - a permission-checked file route;
  - print pages;
  - Admin → Settings → Consent for versions.

**Tech Stack:** Next.js 15, Supabase SQL, Vitest, Playwright. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-23-governance-design.md`, plus the form text in `docs/consent/consent-form-v1.md`. Both are copied from the scratchpad when the branch is created.

## Global Constraints

**Process**
- Work from `web/`.
- The migration is `0072_consent.sql` and is additive. Dry-run it in a rolled-back transaction before `test:db`. 0001–0071 are applied: never edit them.
- Every definer write starts with `app_private.require_perm('patients','edit')`. Version writes use `require_admin`.
- Readers are security invoker, gated by `public.can('patients','view')`. Research readers are also gated by `can('research','view')`.
- Every function sets `search_path = ''` and has an explicit revoke from public, anon and grant to authenticated.
- Business errors use `app_private.fail`.

**File storage**
- **Accepted types:** `image/jpeg` or `application/pdf` only, checked by magic bytes in TS (`sniffConsentFile`) and by a check in SQL.
- **Size limit:** 1 to 2,097,152 bytes. The SQL check enforces it.
- **Browser re-encoding:** images (JPEG, PNG or WebP picked by the user) become JPEG, longest side ≤ 2000 px, quality 0.8.
- **Audit:** `stored_files` has **no audit trigger**. The records that reference a file are audited (file id only).
- **Serving files:** `GET /patients/[id]/consent/file/[fileId]` sends `Content-Disposition: inline`, `Cache-Control: private, no-store`, and `X-Content-Type-Options: nosniff`. It returns 404 when the file doesn't belong to that patient's consent, or when the user lacks Patients view.
- **Upload size:** server-action uploads need `experimental.serverActions.bodySizeLimit: '3mb'` in `next.config.ts`. A 2 MB file is about 2.7 MB as form data. Vercel's limit is 4.5 MB.

**Consent records and versions**
- **Items:** `treatment`, `research`, `teaching_images`, `follow_up`, each boolean and not null.
- **Language:** `en` | `ar`.
- **Signed date:** `signed_on` ≤ `cairo_today()`, and not before the version's `effective_on`.
- **Versions:**
  - The current version is the one with `effective_on ≤ cairo_today()`, latest effective date first, then latest `created_at`.
  - A version is editable until a `patient_consents` row (voided or not) references it. After that, its label, date and texts are locked with the message `This form version has been signed by patients and can't be changed. Add a new version instead.`
  - Labels are unique.
- **Current consent:** the latest non-voided record, by `signed_on` desc then `created_at` desc.
- **`research_consent`:**
  - `yes` or `no` from the current record's `research` item;
  - `not_recorded` when the patient has no current record.

**UI copy (exact)**
- Badge: `No consent on file`.
- Research warning: `⚠ {k} of {n} patients have no research consent on file ({nr} not recorded, {no} refused)`. It shows only when k > 0.
- The about-sheet line is labelled `Research consent`, with the value `{yes} yes, {no} no, {nr} not recorded (of {n} patients)`.
- Answers make no other UI react (owner).

**Docs**
- Add `consent_form_versions` to the restore `TRUNCATE` in `docs/operations.md` §D (it is seeded).
- Add a **Consent (0072)** bullet to CLAUDE.md.

**Styling**
- Design tokens and shared classes only.
- Tables use `className="table"` with `data-label`.

## Review Focus
1. **The file route can't be used to read another patient's file.** A valid `fileId` under a different patient id returns 404, and so does a voided record's file for a user without Patients view. (Task 3 test.)
2. **A version locks the moment it is used.** Recording a consent against v1 makes `save_consent_version` on v1 fail with the exact message, including when that consent is later voided. (Task 1 test.)
3. **A spoofed upload is refused.** A `.pdf` name with PNG/HTML bytes, or a 2,097,153-byte file, is refused in TS with a clear message, and the SQL check refuses it too. (Task 1 and Task 3 tests.)
4. **Voiding the current record falls back.** After voiding the newest record, `research_consent` and the badge reflect the previous record, or `not_recorded` and the badge when none is left. (Task 1 and Task 2 tests.)
5. **The export stays within the allowlist.** `research_consent` has a dictionary entry with values `yes`/`no`/`not_recorded`. No file bytes, version text or file ids appear in any export sheet. (Task 2 test.)

### Task 1: Migration 0072 — files, versions, consents

**Files:**
- Create: `supabase/migrations/0072_consent.sql`, `tests/db/consent.test.ts`, `docs/consent/consent-form-v1.md` (copied from the scratchpad draft)

**Interfaces — Produces:**
- **Tables:**
  - `public.stored_files(id uuid pk, bytes bytea, content_type text, size_bytes int generated, uploaded_by uuid, uploaded_at timestamptz)`
  - `public.consent_form_versions(id uuid pk, label text unique, effective_on date, text_en text, text_ar text, created_at, updated_at)`
  - `public.patient_consents(id uuid pk, patient_id, version_id, language, signed_on, treatment, research, teaching_images, follow_up, file_id → stored_files, recorded_by, created_at, voided_at, voided_by, voided_reason)`
  - Seed v1: label `v1`, `effective_on` = the migration date `2026-10-23`, texts from `docs/consent/consent-form-v1.md` (the English section and the Arabic section, with placeholders kept).
- **Writers** (definer):
  - `record_consent(p_patient uuid, p_version uuid, p_language text, p_signed_on date, p_treatment boolean, p_research boolean, p_teaching_images boolean, p_follow_up boolean, p_file bytea, p_content_type text) returns uuid`. It inserts the file and the record in one transaction.
  - `void_consent(p_id uuid, p_reason text) returns void`. The reason is required (non-blank).
  - `save_consent_version(p_id uuid, p_label text, p_effective_on date, p_text_en text, p_text_ar text) returns uuid`. Admin only. `p_id` null means insert.
- **Readers** (invoker, Patients view):
  - `consent_versions()`, which returns the versions with `in_use boolean`.
  - `current_consent_version()`
  - `patient_consents_for(p_patient uuid)`, which returns every record (current first) with `is_current boolean` and `version_label`, without bytes.
  - `consent_file(p_patient uuid, p_file uuid) returns table(bytes bytea, content_type text)`. It returns no row unless the file belongs to one of that patient's consent records.
- **RLS:** select is gated on Patients view. There are no direct insert, update or delete grants.
