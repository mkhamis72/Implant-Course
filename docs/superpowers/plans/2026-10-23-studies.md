# Studies and ethics approvals (research part 8b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record studies (ethics approval, protocol, courses covered, approval letter), give Research an Edit level, and let an export optionally name a study.

**Architecture:**
- **Migration 0073:**
  - widens the research permission to allow `edit`;
  - adds `studies` and `study_courses`, reusing 8a's `stored_files` for the letter;
  - adds `research_exports.study_id`.
- **Linking an export to a study:** the export carries `study_id` inside the existing `p_filters` jsonb of `log_research_export`. The signature is unchanged, so there is no overload.
- **UI:** a Studies page under Research, a letter route, a Study picker on the export form, and the study in the about sheet and in Recent exports.

**Tech Stack:** Next.js 15, Supabase SQL, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-23-governance-design.md` (goals 9–11 and "Settled after the builder check"). **Depends on 8a being merged** (for `stored_files` and the `src/lib/consent/files.ts` helpers).

## Global Constraints

**Process**
- Work from `web/`.
- The migration is `0073_studies.sql` and is additive. Dry-run it first.
- To change `set_user_permissions` / `log_research_export`, use `create or replace` of the **latest** definitions, found by searching the migrations. Keep the signatures.

**Permissions**
- Research levels become None / View / Edit:
  - drop the `level = 'view'` restriction for `research` (0069 check constraint and `set_user_permissions`);
  - admins always have Edit;
  - `default_permissions()` still gives new organizers None.
- Study writes start with `app_private.require_perm('research','edit')`.
- `delete_study` is admin only. It is refused with `This study is named on an export and can't be deleted.` when any `research_exports.study_id` references it.
- Readers are invoker and gated on `can('research','view')`. They also need Patients view, as the Research page does.

**Study fields**
- Required: `title`.
- Optional: `committee`, `approval_number`, `approval_date` (≤ today), `protocol_name`, `protocol_version`, `protocol_date`, `notes`.
- Also: `study_courses` (course ids) and `letter_file_id` → `stored_files`. The letter follows 8a's file rules: JPEG/PDF, ≤ 2 MB, downscaled in the browser.

**Export**
- The study is a label only (owner): it doesn't change the implant set.
- The about sheet / README gets these rows: `Study` (title), `Ethics committee`, `Approval number`, `Protocol version`. Empty fields show `—`.
- Free text is never exported: `notes` stays out of the file.
- `research_exports.study_id` is set from `p_filters->>'study'`. The function refuses an id that doesn't exist.
- Recent exports shows the study title.

**Letter route**
- `GET /patients/research/studies/[id]/letter` requires Research view and returns 404 otherwise.
- Headers: `inline`, `private, no-store`, `nosniff`.

## Review Focus
1. **The permission grid accepts Research Edit and the DB honours it.** An organizer given Research Edit can save a study. With View they can read but saving is refused. (Task 1 DB test + Task 2 component test.)
2. **The previous app version still works during release.** The old export route calls `log_research_export` without a `study` key and it still succeeds. (Task 1 test.)
3. **A study can't leak through the export.** Study `notes` and the letter never appear in an export. The about rows come only from the allowlisted fields above. (Task 2 test.)
4. **Deleting a study that's in use is refused**, and a non-admin can't delete. (Task 1 test.)
5. **The letter route needs Research view.** A Patients-only user gets 404. (Task 2 test.)
