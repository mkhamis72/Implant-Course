# Statistics (part 7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Show Kaplan–Meier survival with 95% CIs, both as the headline 1- and 2-year tiles and as a band on the curve.
- Let users compare groups: brand/line, technique and risk factors (curves, a table, log-rank), plus a loading table with no test.
- Warn whenever the data is thin.
- Ship an R script with the export.

**Architecture:**
- **Statistics in TS:** pure functions (`src/lib/research/stats.ts`) for KM with Greenwood log-log CIs, log-rank and the chi-square p-value. They are validated against an R-computed fixture.
- **SQL:** migration 0071 adds `implant_outcomes_groups` for the group variables.
- **Research page:** gains CI tiles, the CI band, a "Compare by" panel and the thin-data warnings.
- **Export:** `analysis.R` ships in the export zip and as a download.

**Tech Stack:** TS (no new deps), Supabase SQL, R (`survival`) for the script and fixture generation, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-23-statistics-design.md` (copied from the scratchpad when the branch is created)

## Global Constraints

**Process**
- Work from `web/`. Migration 0071 is additive. Dry-run it before `test:db`.

**Thin data (owner principle)**
- Always show the numbers, and warn when the data is thin.
- Thin means any of: < 30 implants at risk, < 10 failures in a test, or a group with < 5 implants.
- Warning text: `⚠ Not enough data — interpret with caution (n = {n}, {events} failure{s})`.
- Undefined values (zero failures) show `—` with "No failures yet, so this can't be estimated".

**Survival**
- KM time is months = `follow_up_days / 30.4375`, from placement.
- Rows with `event_time_unknown` are excluded, and their count is shown as "{k} failure(s) with unknown date not included".
- CI: Greenwood variance with the log-log transform, the same as R `survfit(conf.type = "log-log")`. Labelled "95% CI".
- Tiles: the KM estimate at day 365 and day 730, with its CI and the number at risk at that point. The SQL milestone breakdown is shown underneath as "status at the milestone", with no %.

**Comparisons**
- Log-rank: chi-square with k−1 degrees of freedom, the same as R `survdiff`.
- Groups:
  - brand (or `brand · system`);
  - technique;
  - smoking (current / former / never);
  - diabetes (yes / no);
  - periodontitis (yes / no);
  - bone type (D1–D4).
- "Not assessed" (null) is its own group, shown but excluded from the test.
- The test runs when ≥ 2 groups have ≥ 1 implant and there is ≥ 1 failure overall.
- p is formatted as `p = 0.034`, or `p < 0.001`.

**Loading**
- Loading groups (immediate / early / conventional / not loaded) come from `loaded_on − placed_on` with the part-3 constants (`LOADING_IMMEDIATE_DAYS`, `LOADING_EARLY_MONTHS` in `src/lib/restorations/`).
- Loading gets a **table only**: no curves and no p-value. Warning: "Late-loaded implants had to survive until loading, so this comparison is biased; no test is shown."

**Notes on the page**
- Clustering, wherever a CI or p appears: "Patients can have several implants; these figures treat implants as independent. Use the R script for patient-clustered models."
- Operator: "Group comparisons here are not adjusted for who placed the implant or the course."

**Display**
- Design tokens only. Group colours come from the existing token palette (`accent`, `ok`, `warn`, `bad`, `ink`, `muted`), and are listed in a legend.

## Review Focus
1. **Agreement with R:** KM and CI values match R `survfit` (log-log) to 4 decimal places, and the log-rank chi-square and p match `survdiff`, on a committed fixture with ties and censoring. (Task 1 test.)
2. **Zero events:** a zero-event group gives S = 1, a CI of "not estimable", and no NaN anywhere. A test with zero failures overall gives `—`. (Task 1 test.)
3. **Tiles and curve agree:** the tile's 1-year value equals the curve's value at 12 months on the same data. (Task 3 test.)
4. **Thin data:** a group with n = 3 and 1 failure still shows its numbers, with the warning. (Task 3 test.)
5. **The R script matches the export:** every column `analysis.R` references exists in `DICTIONARY`. (Task 4 test.)

### Task 1: Statistics library (TS) validated against R

**Files:**
- Create: `src/lib/research/stats.ts` (+ `.test.ts`), `src/lib/research/stats.fixture.json` (generated by R), `scripts/research/gen-stats-fixture.R` (kept for regeneration)
- Modify: `src/lib/research/summary.ts`: `kaplanMeier` delegates to `stats.kmFit` (no behaviour change for points or at-risk)

**Interfaces:**
- Produces:
  - `kmFit(rows: { months: number; event: boolean }[]): { times: number[]; surv: number[]; lower: (number | null)[]; upper: (number | null)[]; nRisk: number[]; nEvent: number[] }`
    - Events are counted before censorings at tied times.
    - Log-log Greenwood CI; null where it can't be estimated.
  - `survivalAtTime(fit, months: number): { surv: number; lower: number | null; upper: number | null; nRisk: number }`: the step function value at that time.
  - `logRank(groups: { months: number; event: boolean }[][]): { chisq: number; df: number; p: number | null }`
    - p is null when there are no events.
  - `chiSquareP(chisq: number, df: number): number`: regularized upper incomplete gamma.
  - `thinData(n: number, events: number): boolean`
  - `formatP(p: number | null): string`: `'p = 0.034'`, `'p < 0.001'`, or `'—'`.
- If R isn't installed locally, write the fixture values by hand from a textbook example: the Freireich 6-MP leukemia data, whose `survfit` / `survdiff` results are published. Say which source you used.
