# Statistics (formerly Research)

Feature rules for this folder, split out of the root `CLAUDE.md` (its conventions still apply). Numbers in brackets are migrations in `web/supabase/migrations/`; the SQL is the source of truth.

- **Research page (0069).** `research` is a permission area with None / View / Edit levels (View only until 0073; Edit is for studies); admins always have Edit, new organizers default to None (`default_permissions()` skips it), delegates never. `implant_outcomes_detail` / `crown_outcomes_detail` are security invoker readers gated on `public.can('research','view')` and also need View on Patients. Summaries and Kaplan–Meier are pure TS over those rows in `src/lib/research/summary.ts` (survival = survived / (survived + failed), shown as "N of M" with not reached and lost to follow-up; under 30 = small sample); filters, labels and drill-down selection are in `src/lib/research/view.ts`. UI: `/statistics` (tiles, inline-SVG survival curve, ICOI bars, complications) and `/statistics/drilldown?list=<key>&filters` (patient lists behind each number); the Statistics nav item (after Delegates) shows only with Research view; the area is labelled "Statistics" (`AREA_LABELS`), and `next.config.ts` redirects the old `/patients/research…` addresses. Tabs (`statistics/layout.tsx`): Results, Studies, Recent exports (admins, `/statistics/exports`). Results opens on `defaultCourse()` (`view.ts`: the most recent course with start ≤ today) when `course` is empty; "All courses" is `course=all` (`ALL_COURSES`, a non-UUID, so `rpcArgs` reads it as no filter). Every filter stays visible (owner rule). Unfiltered All courses, measured 2026-10-25 on 536 local implants: ~0.5 s per reader (admin and organizer), the page ~2 s in dev; the ~7.5 s noted earlier no longer reproduces. E2E specs still filter by a unique brand to isolate their data. A drill-down with no course reads it as All courses (`drilldownFilters`), so old links and their link back agree.
- **Research export (0070).** `GET /statistics/export?format=xlsx|csv&<research filters>` (403 without Research view and Patients view, 400 bad input, 500 failure) returns an anonymised workbook or CSV zip (`research-export-YYYY-MM-DD.xlsx|.zip`, Cairo date) for the implant set of `implant_outcomes_detail` with the page's filters. Eight tables (`implants`, `patients`, `visits`, `radiographs`, `complications`, `restorations`, `restoration_problems`, `grafts`) come from eight security-invoker readers and are paged past the 1000-row cap (`fetchAll`). **Allowlist rule:** every exported column has an entry in `DICTIONARY` (`src/lib/research/export/dictionary.ts`) and the builders refuse anything else; adding a column requires a dictionary entry, free text never (no notes, reasons, other-details, radiograph links, names, phone, email, address, file number, dob). Entities are identified by random study codes (`P-` patient, `I-` implant, `R-` restoration, `D-` delegate, `S-` supervisor, `C-` course; 6 characters, stored once in `app_private.research_codes` and reused). The route first calls `assign_research_codes(filters)` (one insert ordered by entity, id, so concurrent exports can't deadlock), then runs the readers one at a time, ordered date column first (`exportOrder`); the files show the course/delegate filters as codes, raw ids only in the log. Every export is recorded by `log_research_export` in `research_exports` (admins read it; shown on the Recent exports tab). The file carries a confidentiality note (`about` sheet / `README.txt`). Spec: `docs/superpowers/specs/2026-10-23-research-export-design.md`.
- **Studies (0073).** `studies` (title required; committee, approval number/date ≤ today, protocol name/version/date, notes, approval letter in `stored_files` with the consent file rules) and `study_courses` (descriptive). Written through `save_study` (replaces the course set; last write wins), `set_study_letter` / `clear_study_letter` (Research Edit) and `delete_study` (admin; refused once `research_exports.study_id` names it); read through `studies_list()` (Research view + Patients view; `on_export` true only for admins) and `study_letter` via `GET /statistics/studies/[id]/letter` (inline, `no-store`, 404 otherwise). UI: `/statistics/studies` (a tab; edit controls need `canEdit(profile, 'research')`). The export form's optional Study select passes `study=<id>`: a label only (same implants), logged in `research_exports.study_id` by `log_research_export` (unknown id refused), shown by title in Recent exports, and written to the about sheet / README as `Study`, `Ethics committee`, `Approval number`, `Protocol version` (`—` when empty; `studyAboutRows` in `src/lib/research/export/assemble.ts`); notes are never exported. The photo downscale is shared in `src/lib/consent/prepare-scan.ts`.
- **Statistics (0071).** Research tiles show the Kaplan–Meier estimate at day 365 / 730 with a log-log 95% CI (Greenwood, as R `survfit`) and the number at risk; time is `follow_up_days / 30.4375` months, implants with `event_time_unknown` are left out (and counted). KM, log-rank (as R `survdiff`) and thin-data rules are pure TS in `src/lib/research/stats.ts` (fixture from published R values) and `groups.ts`. **Compare by** (`compare=` brand / technique / loading / smoking / diabetes / periodontitis / bone_type) reads the group variables from `implant_outcomes_groups` (0071, security invoker, Research + Patients view); "Not assessed" is its own group, shown but never tested; loading (part-3 constants via `loadingFrom`) gets a table only, no test. Owner principle: always show numbers; thin = < 30 at risk, < 10 failures in a test or a group < 5 → `⚠ Not enough data …`; "—" only when undefined. `src/lib/research/export/analysis.R` (base R + `survival`; KM, `survdiff`, loading table, Cox stratified by course + placing delegate, patient-clustered SEs, EPV warning) ships in the CSV zip and at `/statistics/analysis.R` (Research view); it may use only `DICTIONARY` columns plus its `DERIVED` list (`analysis.test.ts`), and is read from disk at run time (`outputFileTracingIncludes` in `next.config.ts`). Spec: `docs/superpowers/specs/2026-10-23-statistics-design.md`.
- **Explore engine (0078).** Readers `analysis_implants` (one row per placed implant: factors + implant-level outcomes), `analysis_visits` (one row per non-voided visit; `probing_max`, `bop_any`) and `analysis_radiographs` (X-ray × implant on its teeth; empty levels = not measured; `bone_change_mm` against the `visit_grades` baseline) take the six research filters, return the `implant_outcomes_detail` implant set, are security invoker and need Research view and Patients view; no free text (`file_no`/`patient_id` only, for links). The analysis is pure TS in `src/lib/analysis/`: `variables.ts` (registry: kind, role, levels; data-driven levels get labels from the page via `LevelLabels`), `timepoints.ts` (windows placement / early 1–60 / 3 mo 61–135 / 6 mo 136–270 / 12 mo 271–545 / 24 mo 546–910 / later; custom = midpoint target), `observations.ts` (one value per implant per window, closest to the target, later on a tie; never pooled; otherwise one `MissingReason`: not applicable, pending, did not attend, X-ray without measurement, not recorded, no record), `filters.ts` (ANDed; `__none` = not assessed), `choose.ts` (views + method from the kinds), `tests.ts` (Welch, Mann–Whitney, Kruskal–Wallis, chi-square, Fisher, Pearson, Spearman, OLS, Hedges g; checked against published R values in `tests.fixture.json`, generator `scripts/research/gen-analysis-fixture.R`), `quality.ts` (spec warning texts; groups < 3 are shown but not tested), `wording.ts` (no causal or ranking words, "k of n implants", `CAUSATION` line) and `run.ts` (`runAnalysis(data, config, today, labels)`). Delegate, supervisor and course groups are ordered by label. Spec: `docs/superpowers/specs/2026-10-25-explore-clinical-data-design.md`.
- **Explore page.** `/statistics/explore` (tab after Results) loads the three Explore readers plus delegate (also from `implant_outcomes_detail`, for users who can't list delegates), supervisor and course names (`explore/data.ts`, numeric strings coerced), then runs `runAnalysis` in the browser (`explore/workspace.tsx`). It opens on **All courses** (`course=all`). The six research filters stay a GET form (`FilterForm` `keep` carries the analysis); the analysis itself lives in the URL (`src/lib/analysis/url.ts`: `f`, `o`, `w` = timepoint | `all` | `d<from>-<to>`, `v`, `x_<key>` = levels or `min..max`) written with `history.replaceState`, so changes need no server round trip and bad values are dropped. Charts are Apache ECharts 6.1.0 (exact; 5.x has the XSS advisory GHSA-fgmj-fm8m-jvvx), loaded only here (`explore-chart-loader.tsx`, `ssr: false`), SVG renderer, options built and unit-tested in `explore/chart-options.ts`. Colours are `--color-chart-1…6` in `:root` (validated with the dataviz script; plain variables because Tailwind drops unused `@theme` ones), never cycled: groups on a category axis share slot 1, multi-series charts take slots in order and anything past the sixth is muted. Every chart has an `aria-label` summary and a Table view.
- **Saved analyses, print, export (0079).** `saved_analyses` (title, `config` = `{version: 1, query: <Explore URL params>}`, course for context, `created_by`) is read by everyone with Research view + Patients view and written only through `save_analysis` / `delete_analysis` (Research edit; changing needs the creator or an admin; `created_by` makes a user "have records" for `delete_user`). TS: `src/lib/analysis/saved.ts` (allowed keys, `savedHref`), actions in `explore/actions.ts`, list + save form in `explore/saved-analyses.tsx`; opening one is a link to `/statistics/explore?<query>` (the page keys the workspace on its query so it remounts; one on the same six filters opens in place). Print: `/statistics/explore/print?<query>[&alt=1]` renders the report server-side with ECharts SSR SVG (`explore/render-svg.ts`; ECharts escapes labels; custom tooltip formatters return HTML, so they escape every label with `escapeHtml`) and ends with the fixed `LIMITATIONS` text (`explore/report.tsx`). Data: `GET /statistics/explore/export?<query>` assigns study codes, reads them with `analysis_codes` (definer, read only), writes a raw-value CSV (`src/lib/analysis/export-csv.ts`: implant_code, patient_code, group, value, unit, timepoint, days_since_placement, event; a delegate, supervisor or course factor is written as its D-/S-/C- code, never a name; survival rows give months and the event) and logs it with `log_research_export('csv', …, {points})`. Chart downloads (SVG/PNG) come from the client chart instance (`explore/chart-download.ts`).
