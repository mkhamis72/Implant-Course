# Admin

Feature rules for this folder, split out of the root `CLAUDE.md` (its conventions still apply). Numbers in brackets are migrations in `web/supabase/migrations/`; the SQL is the source of truth.

- **Admin user tools (0074).** Admin → Users rows: edit name (`admin_set_name`), **Change email** (Auth first, then `admin_change_email`, which also updates the linked delegate; a DB failure puts the old Auth address back; then sessions end via `admin_end_sessions` and a link-free notice is sent), **Reset 2FA** (only with a verified factor; sets `profiles.mfa_setup_required` via `admin_require_mfa_setup`, deletes the factors, ends sessions), **Resend invite** (never signed in, `EMAIL_ENABLED`), last sign-in, and **History** (`admin_user_history`: audited email/name changes plus `admin_events`; labels in `src/lib/admin/history.ts`, actor may be null). Change email and Reset 2FA refuse your own account (TS and SQL). While the flag is set every session guard sends the user to `/account/security` (`checkPermission` returns `Set up two-factor authentication first.`; only the security page, set-password, sign-out and `/login/*` work), and RLS refuses them too: `app_private.mfa_satisfied()` — behind `is_active_user()`, `is_admin()`, `is_delegate_user()` — is false while it is set; their own profile, permissions and `settings` stay readable. Verifying a new factor calls `mfa_setup_done()` (aal2 + a verified factor created after the latest `mfa_reset` event, self only), which clears it; Reset 2FA always ends sessions once the flag is set and can be retried while it is. `profiles.email` has no UPDATE grant: it changes only with Auth, through `admin_change_email`. Actions in `admin/users/actions.ts`, Auth helpers in `src/lib/admin/auth-accounts.ts`.
