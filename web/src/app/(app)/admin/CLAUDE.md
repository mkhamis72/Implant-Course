# Admin

Feature rules for this folder, split out of the root `CLAUDE.md` (its conventions still apply). Numbers in brackets are migrations in `web/supabase/migrations/`; the SQL is the source of truth.

- **Admin user tools (0074).** Admin → Users rows: edit name (`admin_set_name`), **Change email** (Auth first, then `admin_change_email`, which also updates the linked delegate; a DB failure puts the old Auth address back; then sessions end via `admin_end_sessions` and a link-free notice is sent), **Reset 2FA** (only with a verified factor; sets `profiles.mfa_setup_required` via `admin_require_mfa_setup`, deletes the factors, ends sessions), **Resend invite** (never signed in, `EMAIL_ENABLED`), last sign-in, and **History** (`admin_user_history`: audited email/name changes plus `admin_events`; labels in `src/lib/admin/history.ts`, actor may be null). Change email and Reset 2FA refuse your own account (TS and SQL). While the flag is set every session guard sends the user to `/account/security` (only the security page, set-password, sign-out and `/login/*` work), and RLS refuses them too: `app_private.mfa_satisfied()` — behind `is_active_user()`, `is_admin()`, `is_delegate_user()` — is false while it is set; their own profile, permissions and `settings` stay readable. Verifying a new factor calls `mfa_setup_done()` (aal2 + a verified factor created after the latest `mfa_reset` event, self only), which clears it; Reset 2FA always ends sessions once the flag is set and can be retried while it is. `profiles.email` has no UPDATE grant: it changes only with Auth, through `admin_change_email`. Actions in `admin/users/actions.ts`, Auth helpers in `src/lib/admin/auth-accounts.ts`.
- **Doctors (0114, modules release 3).** Admin → Doctors maintains `public.doctors` (names a Doctor can be chosen as `Placed by` on implants and bookings; same pattern as Supervisors). The admin user tools (0118) are gated by admin only, not by an area permission, so they work in a Clinic too.
- **Doctor logins (0123).** `doctors.user_id` links a Doctor to a login. Create login in a clinic offers Admin / Doctor (organizer shown as "Doctor"), with an existing doctor or a new one, and `Also a doctor` for an admin; `create_pending_login_v2` carries `doctor_id` / `doctor_created`, the sign-up trigger links the doctor, and cancelling an invite deletes a doctor made only for it. Admin → Doctors links/unlinks through `set_doctor_login` (admin). Clinic organizers get Edit on patients, schedule, checklists, inventory and research by default. `add_existing_member_v2` is not used by the app yet.
